Mixedlane is where this team plans and tracks work (Mixedlane MCP server: `mixedlane`).

- **Organization skill:** before each new planning or ticket-writing request, call `get_agent_skill` for the organization's current title/body boilerplates, Markdown conventions, media upload steps and customized rules. It is edited in Settings → AI agents → Organization agent skill and applies to all agents in that organization. Refresh it even in an ongoing session; permissions still apply. If unavailable, reconnect MCP and use the bundled planning skill as a fallback, noting that custom instructions could not be loaded.

- **Scope:** call `whoami` and `list_projects`, respect the connection's project grants and the repository link. Only global mode allows creating projects; it may create multiple projects, so use an existing project when it fits.
- **Before every ticket creation:** search for similar active tickets of the same type in the selected project and the same epic/milestone. Inspect ancestors and acceptance criteria. Update a matching active ticket, preserving useful content, or create if none matches. Never reuse/update/reopen done or released tickets, and keep different epics/milestones separate. If neither level exists, match within the same parent. Ask when multiple matches are ambiguous.

- **When you make a plan or receive requirements** (a feature, a bug list, a spec, "build X"), record the work in Mixedlane with the `create_plan` tool: epic (the outcome) → milestone (if the project uses them) → user story (user value; acceptance criteria as a `- [ ]` checklist) → task (a concrete implementation step) → subtask. Use only the item types the project enables, `search_items` first and reuse what exists. Follow your Mixedlane planning mode (see `whoami`): AUTO → create right away and tell the user the keys; PROPOSE → show the preview and create only after the user approves.
- **While you work**: `start_work` before you start an item; put its key in branch names, commit messages and PR titles (e.g. `APP-0012-add-login`) so GitHub links them; `add_comment` for decisions and blockers; `complete_work` with stage `review` when your part is done (`done` if there is nothing to review).
- **Specs and designs** longer than a few paragraphs go to Mixedlane docs (`create_page`) and mention the item keys so they link both ways.
- **Media:** use `upload_media` (base64 bytes up to 1 MB) or `prepare_media_upload` (single-use multipart URL for larger images/videos), scoped to the work item's project or document space. Embed the returned Markdown only after upload succeeds, verify the stored media with `read_media`, and read back the item/page. Never substitute a data URL for an upload or claim an image rendered just because its description text saved. These tools work with agent authentication without a browser session.
- If the repository has a `.mixedlane.json`, use its `project`. If not and you need one, use the `mixedlane-init` skill to link the repo to a project. For a brand-new initiative with no fitting project, create one with `create_project`; if that's not allowed, tell the user the exact setting named in the error.
